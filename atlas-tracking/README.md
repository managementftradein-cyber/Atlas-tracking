# Atlas Tracking

A parcel & freight tracking site: marketing pages, a public tracking lookup,
a quote/contact form, and a Supabase-backed admin panel to manage shipments —
including proof of delivery (signature + photos) and a shipping-charge calculator.

No build step — plain HTML/CSS/JS. Deploy anywhere that serves static files
(Vercel, Netlify, GitHub Pages) or open `index.html` directly once Supabase is connected.

## 1. Create the Supabase project

1. Go to [supabase.com](https://supabase.com) → New project.
2. Open **SQL Editor** → **New query**, paste the contents of `supabase/schema.sql`, and run it.
   This creates the base tables (`shipments`, `tracking_events`, `quote_requests`,
   `contact_messages`, `admin_users`), Row Level Security, and the `public_tracking` /
   `public_tracking_history` views used by the public tracking page.
3. Run `supabase/admin-v2-migration.sql` **after** the base schema. This adds:
   - `shipment_charges` (shipping-charge calculator)
   - `delivery_confirmations` (proof-of-delivery record: recipient, date, location, notes, signature)
   - `delivery_photos` (delivery photo references)
   - a **private** Storage bucket, `delivery-proof`, with admin-only read/write policies

## 2. Create your admin login

Supabase Auth gates `/admin`. There's no public sign-up form on purpose.

1. **Authentication → Users → Add user** — set an email and password for yourself (and any staff).
2. **Authentication → Providers → Email** → turn off "Allow new users to sign up."
3. Copy the new user's UUID, then in **SQL Editor** run:
   ```sql
   insert into public.admin_users (user_id)
   values ('aa3d71cc-bb15-4f7a-a5ce-a5a88e549592');
   ```
   Only add trusted staff UUIDs here — this table is what grants dashboard access.

## 3. Connect the frontend to your project

Edit `js/config.js` with your project's values (**Project Settings → API**):

```js
window.ATLAS_CONFIG = {
  SUPABASE_URL: "https://xxxxxxxxxxxx.supabase.co",   // bare project URL — no /rest/v1/ suffix
  SUPABASE_ANON_KEY: "sb_publishable_...",             // safe to expose client-side
};
```

The publishable/anon key is meant to be public — it only grants what the RLS policies in
`schema.sql` and `admin-v2-migration.sql` allow. Never put a `service_role`/secret key here.

## 4. Run it

- **Locally:** `npx serve .` from the project root, or open `index.html` directly.
- **Deploy:** drag the folder into Netlify/Vercel, or connect a Git repo. No env vars or
  build command needed — `js/config.js` is the only configuration.

## Day-to-day use

- **New shipment:** Admin → Shipments → New shipment. Fill in the route and details, set the
  charge fields (base, per-kg rate, service, insurance, additional fees — the total calculates
  live), and save.
- **Tracking events:** open a shipment → add events (e.g. "Departed facility," "Arrived at
  customs"). The shipment's status auto-syncs to the latest event, and events populate the
  public tracking timeline in the order added.
- **Proof of delivery:** open a shipment → Proof of delivery section. Record the recipient
  name, date/time, location, and notes; capture a signature on the pad; attach delivery
  photos (JPEG/PNG/WebP). Files are stored in the private `delivery-proof` bucket — only
  admins can view them, via temporary signed URLs generated by the dashboard.
- **Quote requests / messages:** come in automatically from the public forms; mark them
  Contacted/Closed or Read/Closed as you work through them.

## Before going live

- Replace the placeholder contact details in `index.html`, `quote.html`, and `contact.html`
  (`support@yourcompany.com`, `+1 (800) 000-0000`) with your real ones.
- Confirm only your intended staff are listed in `public.admin_users`.
- Test the full flow once in Supabase before treating it as production-final: submit a test
  quote and message, sign in as admin, create a shipment, add an event, record a proof of
  delivery, and search the tracking number on the public site.

## A note on privacy

The public tracking view deliberately leaves out phone numbers, emails, and full street
addresses — a tracking number only reveals shipment status, not a stranger's contact details.
Proof-of-delivery signatures and photos live in a **private** storage bucket, never public.
If you extend the schema, remember: anything added to `shipments` is only public if you also
add it to the `public_tracking` view.
